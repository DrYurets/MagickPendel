# Design

## Context

Каркас прошивки из init-firmware уже работает модульно: settings (NVS),
net (Wi-Fi STA + configTzTime), display, modes. Админка добавляется как
новый модуль + точечные правки в net/settings/display/modes.

## Goals / Non-Goals

**Goals:**
- Синхронный HTTP-сервер на встроенном `WebServer` — админке не нужна
  асинхронность и высокая нагрузка.
- Одна страница (GET `/`) со статусом и формой, POST `/save` — сохранение.
- HTML в PROGMEM-строках — без LittleFS и загрузки файловой системы.
- AP-режим внутри модуля `net`, чтобы вся Wi-Fi-логика оставалась в одном
  месте.

**Non-Goals:**
- Аутентификация/HTTPS — нет, админка открыта в LAN (риск ниже).
- Captive portal (DNS-перехват) — не требуется, адрес виден на экране.
- OTA-обновления, REST API для каналов команд — позже.
- Telegram-бот — только поле токена в настройках, сама интеграция позже.

## Decisions

### WebServer вместо ESPAsyncWebServer
Встроенный `WebServer` из ядра — синхронный, `handleClient()` в loop().
Для одной формы настроек этого достаточно; AsyncWebServer добавил бы
внешние зависимости и колбэк-модель без выигрыша. Альтернатива
отвергнута как избыточная.

### HTML в PROGMEM
Страница — статический шаблон `R"rawliteral"` с подстановкой значений через
`snprintf`/`String`. Альтернатива — LittleFS + файлы — требует шага загрузки
FS-образа при каждой смене вёрстки; строки проще для одной страницы.

### AP-режим: состояния в `net`
`net` получает три состояния: STA (подключён), CONNECTING (пытается),
PROVISIONING (AP + STA-попытки). Переход в PROVISIONING: SSID пуст → сразу;
иначе после ~6 неудачных попыток (~60 с). В PROVISIONING реконнекты к
домашней сети продолжаются (WiFi.mode(WIFI_AP_STA)); при успехе — AP off.
AP: `Pendel-Setup`, открытая, IP 192.168.4.1 (дефолт ESP32).

### Применение настроек после /save
После сохранения: если изменились ssid/pass → перезапуск попытки STA;
если tz → повторный configTzTime. Остальное применяется на лету (modes
читает cfg напрямую). Без ребута.

### Имена детей и токен
`Config` += `child1[24]`, `child2[24]` (UTF-8, дефолты «Ребёнок 1/2»),
`tgToken[80]`. `modes` берёт метки из cfg вместо констант (в верхний регистр
не переводим — показываем как введено).

### Безопасность
Админка без аутентификации — осознанный трейд-офф для домашней сети;
пароль Wi-Fi отдаётся в форме только маской (type=password, value не
подставляется — пустое значение = «не менять»).

## Risks / Trade-offs

- [Открытая админка в LAN] → приемлемо для домашней сети; при желании —
  HTTP Basic Auth отдельным change.
- [Открытая AP Pendel-Setup] → любой рядом может задать свои креденшелы;
  митигация — AP поднимается только пока нет рабочего подключения, окно
  атаки короткое. Отмечено для будущего улучшения (пароль на AP).
- [WebServer блокирует loop на время ответа] → ответы маленькие, задержка
  десятки мс — не мешает кнопке/сигналам.
- [Рост flash/RAM] → страница ~4-6 КБ PROGMEM — помещается (сейчас 79%).
- [sanitize() обрезает новые поля] → добавить валидацию длин новых строк.
