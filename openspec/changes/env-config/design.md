# Design

## Context

Механизм настроек (NVS + дефолты) уже есть; нужен только источник дефолтов
на этапе компиляции. Ранее для Wi-Fi был удалён `secrets.h` — `.env`
занимает ту же роль, но покрывает все настройки и живёт в корне проекта.

## Goals / Non-Goals

**Goals:**
- Один файл `.env` в корне с `#define`-константами; подключение через
  `__has_include` — сборка не ломается без файла.
- `.env` в `.gitignore`; шаблон `.env.example` — в репо.

**Non-Goals:**
- Парсинг dotenv-формата (`KEY=VALUE`) — `.env` содержит C-препроцессорные
  дефайны, потому что значения подставляются при компиляции, без
  дополнительного парсера и шагов сборки.
- Приоритет `.env` над NVS — наоборот, NVS главнее.

## Decisions

### C-дефайны вместо dotenv-синтаксиса
`.env` содержит `#define PENDEL_WIFI_SSID "..."` и т.д. Причина: Arduino
не выполняет pre-build скриптов удобным способом, а превращать .env в
заголовок генератором — лишний шаг. Прямое включение `../.env` из
`settings.cpp` через `__has_include` — ноль инструментария.

### NVS > .env > встроенные дефолты
`settingsLoad()`: сначала дефолты из `.env` (если есть), затем значения из
NVS поверх. Админка по-прежнему главный механизм.

## Risks / Trade-offs

- [Creds в файле на диске] → `.env` в `.gitignore`, пример отдельно.
- [Пользователь запутается в формате] → `.env.example` с комментариями,
  формат `#define` — очевиден для C-проекта.
