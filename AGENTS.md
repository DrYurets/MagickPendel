# Pendel

«Pendel» — физическое устройство для вызова ребёнка (или обоих детей) из детской
комнаты. Родитель отправляет команду — устройство пищит, моргает светодиодом и
показывает на экране, кого зовут и/или текстовое сообщение. В остальное время
работает как информационный дисплей: часы, климат в комнате, обратный отсчёт
до отбоя.

## Аппаратная часть

- **MCU:** ESP32-C3
- **Дисплей:** OLED 128×64, I2C
- **Ввод:** одна физическая кнопка
- **Индикация:** светодиод, активный баззер
- **Датчик климата:** AHT20 (температура, влажность) + BMP280 (давление) на I2C
- **Питание:** от сети (батареи нет — deep sleep между пробуждениями не нужен)
- **Сеть:** постоянное подключение к домашнему Wi-Fi

## Функциональность

### Режим вызова

- Команда приходит от родителя — канал пока не выбран: либо пульт на ESP32-C3,
  либо Telegram-бот.
- Устройство издаёт прерывистый писк и моргает светодиодом в течение N секунд
  (задаётся в настройках) **либо** до нажатия кнопки ребёнком.
- На экране отображается, кого зовут (один ребёнок / оба) и/или текстовое
  сообщение.

### Режим ожидания (idle)

На экране:

- текущее время (синхронизация по NTP);
- температура и влажность в комнате;
- таймер обратного отсчёта до отбоя (по умолчанию 22:00, настраивается).

Предупреждения о приближении отбоя:

- за 15 минут — звуковая и световая индикация;
- за 5 минут — звуковая и световая индикация.

### Режим сна

- По умолчанию с 22:30 до 07:00 (настраивается в админке).
- Дисплей и все индикаторы отключаются.

### Админка

Веб-интерфейс для редактирования настроек. Настраиваемые параметры:

- длительность вызова (N секунд);
- время отбоя (по умолчанию 22:00);
- интервал сна (по умолчанию 22:30–07:00);
- параметры Wi-Fi;
- прочие настройки устройства.

## Технологический стек

- **Фреймворк:** Arduino, ядро `esp32:esp32` 3.3.12 (установлено)
- **Тулчейн:** `arduino-cli` (`~/.local/bin/arduino-cli`) и Arduino IDE.
  Целевая плата: `esp32:esp32:esp32c3` (ESP32C3 Dev Module)
- **Дисплей:** U8g2 (I2C OLED 128×64) — установлена
- **Датчики:** Adafruit AHTX0, Adafruit BMP280 — установлены
- **Время:** NTPClient — установлен
- **JSON:** ArduinoJson — установлена
- **Настройки:** Preferences (NVS) или LittleFS
- **Админка:** встроенный HTTP-сервер (WebServer)

Установленные библиотеки в `~/Arduino/libraries`: U8g2, U8g2_for_Adafruit_GFX,
Adafruit AHTX0 / BMP280 / BusIO / GFX / SSD1306 / SH110X / Unified Sensor,
ArduinoJson, NTPClient, GyverOLED, AutoOTA.

Новые библиотеки ставятся через `arduino-cli lib install <name>` или
Library Manager в Arduino IDE — не копированием в репозиторий.

## Структура репозитория

```
firmware/       Arduino-скетч (firmware.ino + модули .cpp/.h)
openspec/       спецификации и change-предложения OpenSpec
openspec/specs/    текущие спецификации
openspec/changes/  активные предложения об изменениях
```

Имя каталога скетча должно совпадать с именем `.ino` (требование Arduino).

## Рабочий процесс

### OpenSpec

Проект использует [OpenSpec](https://github.com/Fission-AI/OpenSpec) для
управления требованиями и изменениями. Новая функциональность сначала
оформляется как change-предложение (`openspec/changes/`), затем реализуется
и архивируется в `openspec/specs/`.

### Сборка и проверка

```sh
arduino-cli compile -b esp32:esp32:esp32c3 firmware          # сборка
arduino-cli upload  -b esp32:esp32:esp32c3 -p <port> firmware # прошивка
arduino-cli monitor -p <port> -c baudrate=115200              # монитор порта
```

Перед коммитом изменений в `firmware/` прогонять `compile` — это основная
проверка. Скетч также открывается в Arduino IDE (File → Open →
`firmware/firmware.ino`).

### Соглашения

- Документация и openspec-артефакты — **на русском языке**.
- Код пишется под ограничения ESP32-C3: ограниченная RAM, без лишних
  heap-аллокаций в hot path, неблокирующие циклы (millis() вместо delay()
  там, где требуется параллельная реакция на кнопку/сеть).
- Секреты (Wi-Fi пароль, токен Telegram) не коммитятся — выносятся в
  `secrets.h` / `include/secrets.h` (в .gitignore) или вводятся через админку.
- Настройки, редактируемые через админку, должны сохраняться во flash и
  применяться без перепрошивки.
